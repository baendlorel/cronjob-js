✅ F25 单例锁的 key 直接取未规范化的 cx.dir

✅ F26 pm2 cluster 模式下单例锁失效
   改为 server.listen({ path: LOCK_NAME, exclusive: true })：cluster 下不再由 primary 代绑共享句柄。
   node:cluster 模拟：第二个 worker 得到 EADDRINUSE，initialize 照旧 reject。
   真实 pm2 7.1.2 `-i 2`（cluster_mode）：2 个 worker 里只有 1 个 "Cronjob start!"，
     另一个 cronjob() reject "cronjob-js already running"；fork 模式行为不变。
   遗留：被拒的 worker 会被 pm2 反复重启（误用 -i 的部署问题）。
   代码不处理，改为文档约定：runner 用 fork 模式跑，README / CLAUDE.md 已写明。

✅ F27 pm2 restart / stop 会杀掉正在跑的任务
   pm2 默认 treekill，按进程树杀子进程，detached + unref 挡不住（pm2 7.1.2 fork 模式实测：
   restart 时 "process tree killed (2 pids)"，long.js 被杀，且没有 [EXIT]；加 --no-treekill 后存活）。
   修复（仅文档）：README 的 pm2 命令加 --no-treekill 并说明原因、误用 -i 的后果；
   CLAUDE.md 的职责边界与日志章节同步写明。

✅ F28 pause() 之后，进程会在下一个分钟边界自行退出（code 0）
   原因是到点看到 Paused 就直接 return，不再排下一轮；锁 server 又是 unref 的，事件循环随之空掉。
   修复：schedule() 只在 Stopped 时停链；到点分支在 Paused 时照常 schedule()，只跳过 fn。
   实测（结构与 example/main.js 相同）：暂停 90 秒后进程仍存活，resume() 后继续调度，stop() 后正常退出。
   tests/task.test.ts 补了"暂停期间每轮都重排定时器"，并在 stop 用例里断言 jobTimer === null。

🟡 F29 系统时钟往回拨时，同一分钟会再跑一次 —— 不修，与 vixie cron 行为一致
   实测对照 Debian cron 3.0pl1 源码（/usr/sbin/cron）：cron_sync 只做一次对齐，
   之后 TargetTime 每轮固定 += 60，cron_tick 用 TargetTime 而不是 wall clock 判断，
   所以回拨后同一分钟不会重跑（代价是拨快时可能连续跳过几分钟）。
   本项目的循环本来就是"先排下一轮再跑"，回拨后下一次 tick 用的是当前时钟，
   确实会再命中一次；但这只在 NTP 把偏快的钟拨回来时发生，且与 F39 的夏令时重复一致。
   结论：接受为已知行为，不改代码。

🟡✅ F30 dir 里有 FIFO 或卡住的挂载时，runner 会静默停摆
   readFile 打开 FIFO 会一直阻塞，占住 libuv 线程池（默认 4 个）；连续 4 轮后连无关的 fs.readFile 也挂起。
   修复：loadFiles 先 stat，非普通文件（FIFO / 设备 / 目录）跳过并记 WARN，不做 readFile。
   实测：4 个 FIFO + real.js，单轮 17ms 结束，4 条 WARN，real.js 照常命中，无关 readFile 正常。
   nolater（utils.ts）没采用：race 只让 await 提前返回，底层线程仍在 FIFO 上阻塞，
   实测 8 个 FIFO 全部 race 超时后线程池依旧被占满。
   遗留：挂起的网络盘（stat 也会卡）没有解法，触发时线程池同样会被耗光。

🟡✅ F31 每轮都把整个文件读进内存，实际只需要文件头
   修复：stat 已经拿到 size —— <= 64KB 直接 readFile，> 64KB 只定位读前 64KB（header.ts）。
   实测 214MB 的 .js：单轮 346ms / RSS +321MB → 8ms / RSS +1MB，content 恰好 65536 字节，表达式仍能识别。
   2000 个 4KB 小文件的 loadFiles：304ms（逐块循环）→ 65ms（stat + readFile）。
   前 64KB 全是注释才记 WARN（普通大文件不会每分钟刷一条）。

🟡✅ F32 默认 exclude 只排除了顶层 node_modules

   注意：exclude 是整体替换，不合并。

🟡✅ F33 stop() 拦不住正在进行的这一轮
