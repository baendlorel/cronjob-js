══ 已修复 ══════════════════════════════

✅ F1 定时器把「排定时器时的 now」当成「本轮时间」，导致晚一分钟、同一分钟跑两次
   回调里取 new Date()，并截到分钟（setSeconds(0,0)）；若早于边界触发则重排回边界。
   实测 3 分钟每分钟恰好一次；模拟提前 400ms 触发同样每分钟一次。

✅ F2 glob 返回相对路径，导致非 cwd 的 dir 下所有任务 ENOENT
   tryGlobSync 现在返回绝对路径，顺带支持 exclude。

✅ F3 shebang 整行被当成可执行文件名（#!/usr/bin/env node → spawn ENOENT）
   getShebang 返回 {cmd, args}；env node / bash -e / python3 / bash 均已实测。

✅ F4 用 PATH 检测 tsx 却用模块解析加载，.ts 任务静默失败
   cmd = tsx|ts-node|process.execPath，检测与启动同一条 PATH。
   无 tsx 时回退 node，Node 22/26 都能跑通 .ts。

✅ F5 同一文件命中多条 @cron 只 spawn 一次（run() 忽略 count）
   index.ts 按 count 循环：块外 2 条→2 次；块内 2 条→1 次；块内 1+块外 2→3 次。

✅ F6 @cronend 后 group 不归零，块外的 @cron 被并进上一个块
   入列表时写 group: inCronBlock ? group : 0，块外天然为 0。
   嵌套/未闭合/孤立 end 均报错并返回 null。

✅ F7 @cron 后面的说明文字导致整条配置被静默丢弃
   按空白切 token，取前 5 段解析；「0 9 * * * 每天九点」正常命中且无噪音日志。

✅ F8 engines 声明 Node >=16，实际需要 22+ 的 fs.globSync → 已改为 >=22.0.0。

✅ F9 initialize()（单实例锁 / 建目录 / 运行时告警）从未被调用
   cronjob() 为 async 并 await initialize；同 dir 第二实例报 already running 并退出。

✅ F11 cronjob() 用了内部类型且无参调用编译不过
   签名 Partial<UserCronjobConfig>，UserCronjobConfig / TaskController 均已导出。

✅ F12 秒级表达式没有被拒绝，反而被当成另一条 5 段表达式调度
   extract.ts 现在：tokens >= 6 且前 6 段可解析 → 记 Error 并 return null。
   实测：0 0 9 * * * / */5 * * * * * 均被拒绝且不调度；
        「0 9 * * * 每天九点」正常命中，不再有假 Error。

✅ F13 段数不足的表达式被 cron-parser 自动补齐，变成另一条定时
   parse 之前先挡 tokens.length < 5。
   实测：0 9 * * / * * * * 均记 Error 并 return null（不再被补成 0 * 0 9 * *）。

✅ F14 matches() 手比 fields，丢掉了 L 与 dom/dow 的 OR 语义
   matches() 现在直接 expression.includesDate(d)。
   实测：0 9 L * * 于 11/30 命中、11/21 不命中；
        0 9 24 * 1 于周一 23 号与周二 24 号都命中（OR 语义恢复）。

✅ F16 hasTsx 恒为 true，tsx 缺失告警永不触发
   hasTsx = tsCmd !== process.execPath；去掉 PATH 里的 tsx/ts-node 后告警正常输出。

✅ F17 example/main.js 无参调用 cronjob() 编译不过 → 参数已可选。

✅ F18 src/list.ts 已完全失效
   按 TODO 重写为 crontab -l 风格，组合现有函数式模块：
     tryGlobSync → loadFiles → getJobItem → parseExp → next()
   输出：下次运行时间 / 表达式（块内带 [group]）/ 相对路径 / 实际命令。
   实测（含嵌套目录、@cronbegin 块、无 cron 文件、秒级文件）输出正确。
   每条表达式在展示前重新 parse（next() 会推进内部游标，不能复用共享对象）。
   tsc 全绿，list 已从包导出，也支持 `tsx src/list.ts [dir]` 直接运行。

✅ F19 日志标记与 CLAUDE.md 约定不一致
   已改 CLAUDE.md：TAG 统一为 [INFO]/[WARN]/[ERROR]/[SPAWN]/[EXIT]/[DEBUG]，
   并补上三个生命周期事件的确切格式、相对路径约定，以及 <logDir>/<相对路径>.log。

✅ F20 run() 的异常不进主日志
   run.ts 的 catch 现在走 cx.log.err(`path=<相对路径> pid=-1`, e)。
   spawn 前的异常（mkdir / openSync / jobcwd 抛错）都能在主日志定位。

✅ F21 taskFn 是 async，runTask 调用它时不 await 也不 catch
   runTask 现在接受 `void | Promise<void>`：先排下一轮再调用 fn，
   同步异常和 Promise reject 都只记一条 Error，不打断调度链。
   实测：让 fn 每分钟 reject 一次，日志各一条 [ERROR]，unhandledRejections=0，
        两分钟后仍在正常 tick（ticks=2）。

✅ F22 package.json 元信息还是 fluxion 的
   name=cronjob-js，description/description_zh 重写，homepage/repository/bugs 指向本仓库，
   files=[dist, README.md]，exports 补上 ESM 的 types 分支，vitest 移出 dependencies。

✅ 附 cronjobConfig 模块级全局单例 → 已删除，配置只经 cx 传递。
✅ 附 全局 log 单例 → 已改为 cx.log.*，实现可经 config.write 替换。
